# 滴定仪 BLE 通信协议 v3

App 与 ESP32-S3 固件之间的唯一约定。改协议先改本文档，再改两端代码。

v3 相对 v2 的变化：
- 硬件按"外置 pH 模块 + 外置 ADC"、"每通道只在排空端有一个限位开关"、"吸液和排液共用一根管"来约定（第 3 节）。
- 新增错误码 `unhomed`、`no_converge`；明确 `sensor` 的触发条件和停机规则。
- 订阅后设备除了 `state`，还要推送一次 `cal`。
- 补充 BLE 实现约定：消息长度上限、写响应的含义、广播内容、连接数（第 1 节）。
- 给出固件滴定控制环的参考做法（第 4 节）。

v2 相对 v1 的变化：标定算法移到 App（`mv`、`cal_set` / `cal`，删除 `calibrating` 状态和 `cal_*` 命令）；`move` / `jog` 可打断滴定；`limit` 错误带通道和方向。

## 1. GATT 结构

| 项 | UUID | 属性 | 方向 |
|---|---|---|---|
| Service | `f65c0001-8221-4068-aa47-28e41eec47fd` | — | — |
| CMD 特征 | `f65c0002-8221-4068-aa47-28e41eec47fd` | Write（带响应） | App → 设备 |
| EVT 特征 | `f65c0003-8221-4068-aa47-28e41eec47fd` | Notify | 设备 → App |

- 广播包放 flags 和 128 位 Service UUID（共 21 B），设备名（建议 `Titrator-XXXX`）放扫描响应，因为广播包放不下。App 用 Service UUID 把滴定仪排在扫描列表最前。
- 同一时刻只允许 1 个连接，断开后立即重新广播。
- 单条消息不超过 100 B。连接后 App 请求 MTU 247；协商结果小于 103 时，App 判定连接失败并断开。
- 写 CMD 的带响应只表示"已收到"：GATT 写回调只把命令放进队列并返回成功，不回 ATT 错误；执行结果和错误一律通过 `error` 事件上报。
- App 订阅 EVT 后，设备应立即推送一次 `state` 和一次 `cal`。

## 2. 消息格式

每次写入 / 每条通知是**一个** UTF-8 JSON 对象，不分包、不加换行。
数值用 JSON number；pH 保留 2 位小数，电压保留 1 位小数即可。未知字段应忽略，未知 `cmd` / `evt` 应忽略（设备可回 `error`）。

### 2.1 命令（App → 设备，写 CMD）

| `cmd` | 其他字段 | 说明 |
|---|---|---|
| `titrate` | `target`: 目标 pH（0–14，2 位小数） | 开始自动滴定，做法见第 4 节。pH 高于目标加酸（通道 1），低于目标加碱（通道 2） |
| `stop` | — | 立即停止所有电机和滴定，回到 `idle` |
| `move` | `ch`: 1 / 2，`dir`: `"in"` / `"out"` | 单步动作：`in` 吸液（电机反转），`out` 排液（电机正转），步长由固件定。同一通道同一方向的单步可以累加 |
| `jog` | 同 `move` | 持续动作。App 在按住按钮期间每 300 ms 重发一次；设备超过 1000 ms 未收到新的 `jog` 必须自动停止 |
| `cal_set` | `slope`: 斜率（mV/pH，负数），`offset`: 零点（pH 7 时的 mV） | 保存标定参数（掉电不丢）并立即生效，回 `cal` 事件。`slope` 超出 −70…−40 或 `offset` 超出 −100…100 时回 `error: bad_cmd` |

`move` / `jog` 的通道或方向与正在进行的动作不同时，设备停止当前动作，改做新的动作。

示例：`{"cmd":"titrate","target":7.00}`、`{"cmd":"jog","ch":1,"dir":"in"}`、`{"cmd":"cal_set","slope":-57.92,"offset":4.35}`

### 2.2 事件（设备 → App，EVT 通知）

| `evt` | 字段 | 说明 |
|---|---|---|
| `ph` | `v`: 当前 pH，`mv`: 电极电压（mV） | 固定 2 Hz 上报。`mv` 按第 2.4 节定义；`v` 由设备用当前标定参数从 `mv` 算出。设备没有实时时钟，时间戳由 App 在收到时打 |
| `state` | `s`: `idle` / `titrating` / `moving` | 状态变化时上报，订阅后立即上报一次 |
| `cal` | `slope`、`offset` | 设备当前保存的标定参数。订阅后上报一次，`cal_set` 生效后再回一次 |
| `error` | `code`: 错误码，可选 `msg`: 说明；`limit` / `unhomed` 时还有 `ch`、`dir` | 见下表 |

示例：`{"evt":"ph","v":6.98,"mv":1.2}`、`{"evt":"state","s":"titrating"}`、`{"evt":"error","code":"limit","ch":1,"dir":"in"}`

### 2.3 错误码

| `code` | 含义 |
|---|---|
| `busy` | 当前状态不允许该命令（如移动中收到 `titrate`） |
| `limit` | 注射器到达行程端点。`ch` / `dir` 是撞到端点的动作：`dir: "out"` 表示已排空（排空端限位开关触发，滴定中试剂用完也是它），`"in"` 表示已吸满（软限位） |
| `unhomed` | 该通道上电后还没排空过，位置未知，拒绝吸液（`dir: "in"`）。先排液到底一次即可 |
| `no_converge` | 滴定不收敛（目标附近 pH 变化太陡），设备已自动停止 |
| `sensor` | pH 电极或测量前端异常 |
| `bad_cmd` | 无法解析或参数非法 |

设备自行停止滴定或动作时（`limit`、`no_converge`、`sensor`），先发 `error`，再发 `state: idle`。

### 2.4 电压和 pH 换算

`mv` 是**折算到电极端**的电压，不是 ADC 读到的电压。外置 pH 模块的输出是"偏置 + 增益 × 电极电压"，由固件换算：

```
mv = (V_adc − FE_BIAS_MV) / FE_GAIN
pH = 7 + (mv − offset) / slope
```

- `FE_GAIN`、`FE_BIAS_MV` 是固件常量（`FE_GAIN` 含分压比）。联调时先用模块电位器把偏置调到 ADC 量程中间，再把 BNC 短接（电极端 0 mV），实测得到 `FE_BIAS_MV`。`FE_GAIN` 按模块原理图取值，或用两个已知电压实测。
- 电位器调好后不要再动；动过之后，要重新测 `FE_BIAS_MV`，然后在 App 里重新标定。
- 标定参数出厂默认 `slope = −59.16`、`offset = 0`（25 °C 理想电极）。不做温度补偿。

## 3. 行为约定

- **断开即停**：BLE 连接断开时，设备必须立即停止所有电机（滴定也停止）。
- **滴定完成由 App 判定**：滴定中 App 连续 5 s 读到 `|pH − target| ≤ 0.05`，且这 5 s 内读数的极差 ≤ 0.03（与第 4 节的 `SETTLE_SPAN` 相同，联调时两者一起调），即判定完成，发送 `stop` 并提醒用户。
- **吸排液随时可用**：用户可以在任何时候点按或长按吸液、排液，包括滴定中。设备在 `titrating` 下收到 `move` / `jog` 时结束滴定，开始动作，并上报 `state: moving`。吸液和排液共用一根管，所以吸液前由用户把管口放进试剂瓶，设备不做判断。

| 状态 | 接受的命令 | 其余命令 |
|---|---|---|
| `idle` | 全部 | `error: busy` |
| `titrating` | `stop`、`move`、`jog` | `error: busy` |
| `moving` | `stop`、`move`、`jog` | `error: busy` |

- **注射器位置**：每个通道只在排空端（排液到底）有一个限位开关。
  - 开关触发时，停止排液，该通道步数清零，记为"已归位"，并回 `limit`（`dir: "out"`）。开关已经触发时，再收到排液命令，直接回 `limit`。
  - 吸满端用常量 `STROKE_STEPS` 做软限位：已归位的通道吸到 `STROKE_STEPS` 时停止，并回 `limit`（`dir: "in"`）。
  - 上电后、该通道触发过一次开关之前，位置未知：吸液回 `unhomed`，排液和滴定照常进行。步数只存在 RAM 里，不写 NVS。
- **电极异常**：读数贴近 ADC 量程两端并持续 2 s 时，判定为 `sensor` 异常，只在进入异常时发一次。滴定中出现异常，先发 `error` 再回 `idle`。异常期间收到 `titrate`，回 `error: sensor`。`ph` 照常上报。
- **标定在 App 完成**：设备没有标定状态，也不做标定计算，只负责上报 `mv`、保存 `cal_set` 下发的参数，并按第 2.4 节换算 pH。App 的做法（仅供参考，设备不依赖）：
  1. 依次引导用户把电极放入缓冲液：先中性（6.86 或 7.00），再酸性（4.00 / 4.01），可选碱性（9.18 / 10.01），至少 2 个点。
  2. 每个点等读数稳定：最近 10 个读数（5 s）的 `mv` 极差 ≤ 1.0 mV，取它们的平均值；60 s 内不稳定，提示重试。
  3. 用最小二乘拟合 `mv = offset + slope × (pH − 7)`。
  4. 斜率在理想值的 85 %–105 %（−50.3…−62.1 mV/pH）且 `|offset| ≤ 60 mV` 时，才下发 `cal_set`；否则提示检查电极和缓冲液。

## 4. 滴定控制环（固件参考做法）

以下参数都做成固件常量（`config.h`），联调时再调。`lib/sim/sim_titrator.dart` 按这里实现，可以对照。

1. **等稳定**：每次加液后，先丢弃 `SETTLE_SKIP`（2 s）内的读数；之后最近 `SETTLE_N`（8 个，4 s）读数的极差 ≤ `SETTLE_SPAN`（0.03 pH）即视为稳定。超过 `SETTLE_MAX`（30 s）仍不稳定，就按当前读数继续。
2. **保持带**：`|pH − target| ≤ HOLD_TOL` 时不加液。`HOLD_TOL` 必须小于 App 的完成带 0.05，建议 0.02。
3. **剂量**：第一剂用 `FIRST_DOSE`。之后用上一剂实测的响应（ΔpH / ΔV）估算到达目标还需要的体积，乘 0.5，再限幅到 [`MIN_DOSE`, `MAX_DOSE`]。响应不可用时（ΔpH 太小或方向不对），剂量取上一剂的 2 倍，同样限幅。
4. **不收敛**：需要的加液方向和上一剂相反，记为一次换向，换向后剂量减半。累计第 3 次换向，或者上一剂已经是 `MIN_DOSE` 仍然换向，就停止滴定：先发 `error: no_converge`，再发 `state: idle`。
5. **注射器常量**：`UL_PER_STEP`、`MOVE_UL`（单步体积）、速度、加速度、反向间隙步数、`STROKE_STEPS`。
