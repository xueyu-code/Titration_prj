# 滴定仪 BLE 通信协议 v2

App 与 ESP32-S3 固件之间的唯一约定。改协议先改本文档，再改两端代码。

v2 相对 v1 的变化：
- 标定算法移到 App：设备上报电极原始电压 `mv`，App 计算斜率 / 零点后用 `cal_set` 下发；删除 `calibrating` 状态、`cal_start` / `cal_point` / `cal_finish` / `cal_abort` 命令和 `cal_point` / `cal_done` 事件。
- `move` / `jog` 在滴定中也接受，会打断滴定。
- `limit` 错误带上触发它的通道和方向。

## 1. GATT 结构

| 项 | UUID | 属性 | 方向 |
|---|---|---|---|
| Service | `f65c0001-8221-4068-aa47-28e41eec47fd` | — | — |
| CMD 特征 | `f65c0002-8221-4068-aa47-28e41eec47fd` | Write（带响应） | App → 设备 |
| EVT 特征 | `f65c0003-8221-4068-aa47-28e41eec47fd` | Notify | 设备 → App |

- 广播包或扫描响应里应包含 Service UUID 和设备名（建议 `Titrator-XXXX`），App 用它把滴定仪排在扫描列表最前。
- 连接后 App 请求 MTU 247，单条消息不得超过 `MTU - 3` 字节（244）。
- App 订阅 EVT 后，设备应立即推送一次 `state`。

## 2. 消息格式

每次写入 / 每条通知是**一个** UTF-8 JSON 对象，不分包、不加换行。
数值用 JSON number；pH 保留 2 位小数，电压保留 1 位小数即可。未知字段应忽略，未知 `cmd` / `evt` 应忽略（设备可回 `error`）。

### 2.1 命令（App → 设备，写 CMD）

| `cmd` | 其他字段 | 说明 |
|---|---|---|
| `titrate` | `target`: 目标 pH（0–14，2 位小数） | 开始自动滴定。设备根据当前 pH 与目标值控制两路注射器加液：pH 高于目标加酸（通道 1），低于目标加碱（通道 2），接近目标时应减小单次加液量 |
| `stop` | — | 立即停止所有电机和滴定，回到 `idle` |
| `move` | `ch`: 1 / 2，`dir`: `"in"` / `"out"` | 单步动作：`in` 吸液（电机反转），`out` 排液（电机正转），步长由固件定。同一通道同一方向的单步可以累加 |
| `jog` | 同 `move` | 持续动作。App 在按住按钮期间每 300 ms 重发一次；设备超过 1000 ms 未收到新的 `jog` 必须自动停止 |
| `cal_set` | `slope`: 斜率（mV/pH，负数），`offset`: 零点（pH 7 时的 mV） | 保存标定参数（掉电不丢）并立即生效，回 `cal` 事件。`slope` 超出 −70…−40 或 `offset` 超出 −100…100 时回 `error: bad_cmd` |

`move` / `jog` 的通道或方向与正在进行的动作不同时，设备停止当前动作，改做新的动作。

示例：`{"cmd":"titrate","target":7.00}`、`{"cmd":"jog","ch":1,"dir":"in"}`、`{"cmd":"cal_set","slope":-57.92,"offset":4.35}`

### 2.2 事件（设备 → App，EVT 通知）

| `evt` | 字段 | 说明 |
|---|---|---|
| `ph` | `v`: 当前 pH，`mv`: 电极电压（mV） | 周期上报，建议 2 Hz（不低于 1 Hz）。`v` 由设备按第 2.4 节用当前标定参数从 `mv` 算出。设备没有实时时钟，时间戳由 App 在收到时打 |
| `state` | `s`: `idle` / `titrating` / `moving` | 状态变化时上报，订阅后立即上报一次 |
| `cal` | `slope`、`offset` | 对 `cal_set` 的确认，回传设备实际保存的参数 |
| `error` | `code`: 错误码，可选 `msg`: 说明；`limit` 时还有 `ch`、`dir` | 见下表 |

示例：`{"evt":"ph","v":6.98,"mv":1.2}`、`{"evt":"state","s":"titrating"}`、`{"evt":"error","code":"limit","ch":1,"dir":"in"}`

### 2.3 错误码

| `code` | 含义 |
|---|---|
| `busy` | 当前状态不允许该命令（如移动中收到 `titrate`） |
| `limit` | 注射器到达行程极限。`ch` / `dir` 是撞到极限的动作：`dir: "in"` 表示针筒已吸满，`"out"` 表示已排空（滴定中试剂用完也是 `"out"`） |
| `sensor` | pH 电极异常 |
| `bad_cmd` | 无法解析或参数非法 |

### 2.4 pH 换算

```
pH = 7 + (mv − offset) / slope
```

出厂默认值 `slope = −59.16`、`offset = 0`（25 °C 的理想电极）。不做温度补偿。

## 3. 行为约定

- **断开即停**：BLE 连接断开时，设备必须立即停止所有电机（滴定也停止）。
- **滴定完成由 App 判定**：滴定中 App 连续 5 s 读到 `|pH - target| ≤ 0.05` 即判定完成，发送 `stop` 并提醒用户。设备自行停止（如到达极限）时先发 `error` 再发 `state: idle`。
- **吸排液随时可用**：用户可以在任何时候点按或长按吸液、排液，包括滴定中。设备在 `titrating` 下收到 `move` / `jog` 时结束滴定，开始动作，并上报 `state: moving`。

| 状态 | 接受的命令 | 其余命令 |
|---|---|---|
| `idle` | 全部 | — |
| `titrating` | `stop`、`move`、`jog` | `error: busy` |
| `moving` | `stop`、`move`、`jog` | `error: busy` |

- **标定在 App 完成**：设备没有标定状态，也不做标定计算，只负责上报 `mv`、保存 `cal_set` 下发的参数并按第 2.4 节换算 pH。App 的做法（仅供参考，设备不依赖）：
  1. 依次引导用户把电极放入缓冲液：先中性（6.86 或 7.00），再酸性（4.00 / 4.01），可选碱性（9.18 / 10.01），至少 2 个点。
  2. 每个点等读数稳定：最近 10 个读数（约 5 s）的 `mv` 极差 ≤ 1.0 mV，取它们的平均值；60 s 内不稳定则提示重试。
  3. 用最小二乘拟合 `mv = offset + slope × (pH − 7)`。
  4. 斜率在理想值的 85 %–105 %（−50.3…−62.1 mV/pH）且 `|offset| ≤ 60 mV` 才下发 `cal_set`，否则提示检查电极和缓冲液。
